# Oracle EBS 兼容方案 - 技术分析

## 问题本质

```
Oracle EBS → Java Applet (NPAPI) → 浏览器 → JRE 6u7+ → x86/ARM硬件
```

**核心矛盾：**
- JRE 6u7~8 为 x86 架构，ARM64 无法原生运行
- 现代浏览器已移除 NPAPI 插件支持（Chrome ≥45, Firefox ≥57）
- Oracle EBS 依赖 Java Applet，必须通过 NPAPI 加载

## 架构差异

| 维度 | ARM64 | X86/C86 |
|------|-------|---------|
| JRE运行 | 需要模拟层 | 原生运行 |
| 浏览器 | 模拟环境内运行 | 直接安装 |
| 性能 | 有损耗(模拟) | 零损耗 |
| 复杂度 | 高 | 低 |
| 推荐方案 | QEMU虚拟机 | Firefox 52 ESR + OpenJDK 8 |

## Java 运行环境选择

### 方案一：Oracle JRE（手动下载）

Oracle JRE 6u7/7/8 是 Oracle EBS 官方推荐的运行时。

**插件文件位置：**
- 32位: `${JRE_HOME}/lib/i386/libnpjp2.so`
- 64位: `${JRE_HOME}/lib/amd64/libnpjp2.so`

**配置步骤：**
1. 从 Oracle 官网下载 JRE tar.gz 或 .bin 安装包
2. 解压到 `/opt/jre`
3. 创建软链接到浏览器插件目录：
   ```bash
   sudo ln -sf /opt/jre/lib/amd64/libnpjp2.so ~/.mozilla/plugins/
   sudo ln -sf /opt/jre/lib/amd64/libnpjp2.so /usr/lib/mozilla/plugins/
   ```
4. Oracle JRE 7/8 需在 Java 控制面板添加 EBS 站点例外

**V3.1 修复的安装问题：**
- `.bin` 自解压包必须以绝对路径执行（`sudo /tmp/jre-6u7-*.bin`），v3.0 的 `./` 拼接会导致路径错误
- JRE 6u7 的 `.bin` 解压出 `jre1.6.0_07` 目录，必须将该目录本身作为 `/opt/jre`（而非嵌套进其内部），否则 `bin/java` 验证必然失败

### 方案二：OpenJDK 8 + IcedTea（自动安装）⭐ 推荐

OpenJDK 是 JRE 的开源实现，IcedTea-Web 提供 NPAPI Java Applet 支持。

**为什么只推荐 OpenJDK 8？**

| OpenJDK 版本 | IcedTea-Web 兼容性 | Applet 支持 | 说明 |
|-------------|-------------------|------------|------|
| **8** | ✅ 完全兼容 | ✅ 可用 | IcedTea-Web 原生基于 Java 8 |
| 11 | ❌ 不兼容 | ❌ 不可用 | IcedTea-Web 不支持 Java 11+ |
| 17 | ❌ 不兼容 | ❌ 不可用 | 同上 |

**Debian/Ubuntu 安装：**
```bash
sudo apt-get install openjdk-8-jre icedtea-8-plugin
# 或（包名因发行版而异）
sudo apt-get install openjdk-8-jre icedtea-web
```

**RedHat/CentOS 安装：**
```bash
sudo yum install java-1.8.0-openjdk icedtea-web
```

**IcedTea 插件文件位置：**
- Debian系: `/usr/lib/icedtea-web/IcedTeaPlugin.so`
- RedHat系: `/usr/lib/jvm/java-1.8.0-openjdk-*/jre/lib/*/libnpjp2.so`

**优势：**
- 包管理器一键安装，无需手动下载
- IcedTea 插件自动提供 NPAPI 支持
- 无需额外配置 Java 控制面板（Applet 安全提示更少）

## X86方案原理

```
X86主机 → Firefox 52 ESR + NPAPI Java插件 → Java运行时 → Oracle EBS
                ↓
    Oracle JRE 6u7/7/8 (手动)  或  OpenJDK 8 + IcedTea (自动)
```

无需任何中间层，直接安装：
1. 安装 Firefox 52 ESR（最后支持NPAPI的官方版）或 Pale Moon（官方持续支持NPAPI）或 SeaMonkey 2.49.5（最后支持Java NPAPI的SeaMonkey版本，禁止升级到2.53+）
2. 安装 Java 运行时（Oracle JRE 或 OpenJDK 8 + IcedTea）
3. 浏览器 Java 插件自动配置（脚本处理软链接）
4. Oracle JRE 7/8 需添加站点例外（OpenJDK 8 通常不需要）

## ARM方案原理

```
ARM64主机 → QEMU/Box64模拟 → x86 Linux → x86 Firefox + x86 Java → Oracle EBS
```

需要x86模拟层：
1. QEMU全系统VM（最稳定，推荐内存≥4GB）
2. QEMU用户模式+proot（轻量级）
3. Box64+Wine（技术探索）
4. Docker+QEMU（容器化）
5. Box86（备选，仅支持32位x86）

## JRE版本策略

```
Oracle JRE 6u7 ─→ 直接使用，无安全提示
Oracle JRE 7   ─→ Java控制面板 → 安全 → 站点例外 → 添加EBS地址
Oracle JRE 8   ─→ Java控制面板 → 安全 → 站点例外 → 添加EBS地址
OpenJDK 8      ─→ 通常无需站点例外，IcedTea-Web自动处理
```

**自动配置方式（V3.1已更正）：**

配置必须写入**真实桌面用户**的家目录（sudo运行时 `$HOME=/root` 是错误的，应通过 `SUDO_USER` 定位）：

```bash
mkdir -p ~/.java/deployment
echo "https://ebs.example.com" >> ~/.java/deployment/exception.sites
# V3.1更正: 配置文件名是 deployment.properties (v3.0误写为deployment.security，无效)
cat > ~/.java/deployment/deployment.properties << 'EOF'
deployment.security.level=MEDIUM
deployment.security.sandbox.aws.warning.level=allow_unsigned
EOF
```

> 注意：JRE 8u60+ 已废弃 MEDIUM 安全级别，站点例外（exception.sites）是唯一可靠途径。

### 经验总结

1. **sudo模式的隐性问题**：脚本内所有 `~`、`$HOME`、`cat > 系统目录` 都会受运行身份影响，必须显式处理 SUDO_USER
2. **bash单行export陷阱**：`export A=1 B=$A` 中 `$A` 在 export 执行前展开，取到旧值
3. **heredoc变量展开**：需要注入宿主变量的启动脚本用非引用定界符并转义运行时变量；纯静态脚本用引用定界符
4. **仓库浏览器不可用于Applet**：任何Debian 10+仓库的firefox-esr都无NPAPI，模拟环境内也必须用FF52二进制
5. **set -e与部分失败**：辅助组件（如插件）缺失不应让主流程（Java本体）的成果清零
6. **"社区维护就还支持NPAPI"不能凭直觉**：SeaMonkey与Pale Moon同为Firefox分支，用户的质疑完全合理；必须去官方Release Notes/Legacy页面核实，不能沿用印象。核实结果分叉：Pale Moon确认持续保留，SeaMonkey在2.53.5+已彻底移除Java NPAPI
